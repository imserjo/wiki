# Дорожная карта развития проекта "База знаний"

## 🎯 Верхний приоритет — то, что реально пригодится

### 1. Alembic — миграции вместо `create_all()`

Сейчас таблицы создаются автоматически при старте (`Base.metadata.create_all`). Это работает, но есть проблема: **любое изменение схемы** (добавить поле, изменить тип, переименовать колонку) потребует либо вручную лезть в БД, либо удалять её и терять данные.

Alembic решает это: генерирует SQL-миграции, применяет их пошагово, позволяет откатываться.

**Что даёт:**
- Меняете `models.py` → `alembic revision --autogenerate -m "add field"` → `alembic upgrade head`.
- История изменений схемы в git.
- Безопасное обновление прода без потери данных.

**Сложность:** средняя. Час-два на настройку.

### 2. Тесты на pytest

Сейчас у вас **ноль тестов**. Любая правка может что-то сломать незаметно. Минимальный набор:

- Регистрация и логин.
- Создание/редактирование/удаление заметки.
- Фильтр по тегу, поиск.
- Экспорт CSV/Excel.
- CSRF (если добавите).
- Разграничение доступа (юзер A не видит заметки юзера B).

**Что даёт:**
- Уверенность при рефакторинге.
- Быстрая проверка, что ничего не сломалось.
- Тесты = документация поведения.

**Сложность:** средняя. Нужна отдельная тестовая БД (SQLite в памяти или отдельная PostgreSQL).

### 3. Полнотекстовый поиск на PostgreSQL

Сейчас поиск в `crud.list_notes` — это `ILIKE %text%`. Работает, но:
- Не ищет по формам слов («заметка» vs «заметки»).
- Медленно на больших объёмах.
- Нет ранжирования по релевантности.

PostgreSQL умеет `tsvector` + GIN-индекс — это встроенный full-text search. Работает быстро и с русским языком (нужен словарь `russian`).

**Что даёт:**
- Поиск по морфологии.
- Ранжирование результатов.
- Скорость на тысячах заметок.

**Сложность:** средняя. Нужно добавить колонку, индекс, триггер или пересчёт при сохранении.

## 🎁 Средний приоритет — полезно, но не критично

### 4. Пагинация списка заметок

Сейчас `/notes` показывает **все** заметки разом. Если их станет 500 — страница будет грузиться долго.

**Что даёт:** разбивка по 20-50 заметок, навигация «вперёд/назад».

**Сложность:** низкая. Один параметр `page` в роуте, `limit/offset` в `crud`, пара ссылок в шаблоне.

### 5. Загрузка изображений

Сейчас картинки в заметке можно вставить только по ссылке (`![alt](https://...)`). Локальная загрузка была бы удобнее.

**Что даёт:**
- Drag&drop картинки в форму.
- Сохранение в `app/static/uploads/`.
- Вставка Markdown-ссылки автоматически.

**Сложность:** средняя. Нужен эндпоинт для загрузки, валидация (размер, тип), уникальные имена файлов, очистка при удалении заметки.

### 6. Автосохранение черновика

Если браузер закроется или упадёт — заметка потеряется. Можно сохранять черновик в localStorage каждые 5-10 секунд.

**Что даёт:** восстановление несохранённого текста при возврате на форму.

**Сложность:** низкая. Только JS на клиенте, сервер не трогаем.

### 7. Теги — автодополнение

Сейчас теги вводятся как текст через запятую. Если тегов много — легко опечататься и создать дубликат.

**Что даёт:**
- Выпадающий список существующих тегов.
- Наглядная подсветка «новый тег / существующий».
- Меньше дубликатов.

**Сложность:** средняя. Нужен эндпоинт `/api/tags` (который мы удалили) — вернуть его как внутренний, плюс JS на клиенте.

### 8. Версионирование заметок

Каждое сохранение — новая версия. Можно посмотреть историю и откатиться.

**Что даёт:**
- История изменений.
- Откат к предыдущей версии.
- Diff между версиями.

**Сложность:** высокая. Нужна таблица `note_versions`, логика при сохранении, UI для просмотра.

## 🎨 Низкий приоритет — приятные мелочи

### 9. Тёмная тема

CSS-переключатель + переменные. Браузер запоминает выбор в localStorage.

**Сложность:** низкая. Час работы.

### 10. Хлебные крошки

`Главная → Тег python → Заметка "..."` — удобная навигация.

**Сложность:** низкая.

### 11. Массовые операции в списке

Чекбоксы → «удалить выбранные», «добавить тег к выбранным».

**Сложность:** средняя.

### 12. Экспорт одной заметки в PDF

Если заметка — что-то вроде документации, PDF удобно распечатать или переслать.

**Сложность:** средняя. Нужен `weasyprint` или `pdfkit`, сложно с настройкой.

### 13. RSS-фид

Лента последних заметок. Может быть полезно, если ведёте публичную базу знаний.

**Сложность:** низкая.

## 🏗️ Архитектурные улучшения

### 14. Логирование

Сейчас `uvicorn` пишет в консоль. В продакшене нужны логи в файлы с ротацией.

**Что даёт:** история запросов, отладка ошибок, аудит.

**Сложность:** низкая. `logging.config.dictConfig` + `RotatingFileHandler`.

### 15. Health-check и мониторинг

Эндпоинт `/health` с проверкой БД. Плюс метрики (Prometheus) — если будете деплоить.

**Сложность:** низкая-средняя.

### 16. Docker Compose

Один `docker-compose up` — поднимается и PostgreSQL, и приложение. Забудете про «а как запустить на другом компьютере?».

**Сложность:** средняя. Нужен `Dockerfile` + `docker-compose.yml`.

### 17. Деплой на сервер

Настройка nginx + systemd (или gunicorn + uvicorn workers), HTTPS через Let's Encrypt.

**Сложность:** высокая, но одна из самых полезных вещей — сделает проект доступным с любого устройства.

## 🎯 Что бы я посоветовал для вашего проекта

Судя по тому, что вы дошли до Markdown + Pygments, вы в хорошем темпе. Дальнейшие шаги зависят от цели:

**Если хотите продолжать использовать лично:**
- **Пагинация** (п.4) — быстро, полезно.
- **Автосохранение** (п.6) — быстро, спасает от потери текста.
- **Теги — автодополнение** (п.7) — заметно улучшает UX.
- **Тёмная тема** (п.9) — приятно.
- **Docker Compose** (п.16) — чтобы легко запускать на другом компьютере.

**Если хотите выложить в интернет:**
- **Alembic** (п.1) — обязательно для безопасных обновлений.
- **Тесты** (п.2) — хотя бы минимальные.
- **Логирование** (п.14).
- **Деплой** (п.17) — nginx + HTTPS.

**Если хотите улучшить качество кода:**
- **Alembic** + **тесты** + **логирование**.

## 📌 Практическая рекомендация

Порядок, который я бы предложил:

6. **Docker Compose** (п.16) — час, легко развернуть где угодно.
